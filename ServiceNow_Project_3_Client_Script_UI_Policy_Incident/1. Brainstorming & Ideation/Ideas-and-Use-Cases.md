# Ideas and Use Cases

## Use Case 1 – High Priority Incident

When Priority is high, make an additional explanation field mandatory.

## Use Case 2 – State Based Behavior

When an Incident reaches a selected state, make selected fields read-only.

## Use Case 3 – Conditional Visibility

Show an additional field only when the related condition is satisfied.

## Use Case 4 – Client Validation

Before submission, validate a field and prevent submission if the value is invalid.

## Recommended Scope

For the project demonstration, implement at least:

1. One UI Policy for mandatory behavior.
2. One UI Policy for read-only behavior.
3. One Client Script for dynamic behavior.
4. One Client Script for validation.
